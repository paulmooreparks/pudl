    PUDL, the Pleasantly Usable Design Language

    PUDL is a control grammar modelled on the conventions of desktop toolkits such as GTK: raised buttons, sunken inputs, segmented controls, a master-detail layout, filter chips, key/value tables, switches and server-rendered dialogs. Elevation signals interactivity, so raised means pressable, sunken means input and flat means display. Colour is never the only signal, and every meaningful state carries a glyph.

    1. Tokens

    A theme sets the tokens below for light and dark, and PUDL derives every other token from them. The default palette shown here is a neutral graphite. A topbar containing a menu bar uses a light surface in the light theme and dark graphite in the dark theme. Each menu group forms one slightly raised surface. A project may replace the palette. A change to the accent reaches links, primary buttons, focus rings, filter chips, accent badges, the current list row, selected table rows, a switch that is on and the active window.

    2. Buttons

    Every button is raised, because a button can be pressed, and there is no flat button. A disabled button is dimmed but stays raised, since it is still a button, only one that does nothing yet. A disabled button of any kind, primary and danger included, looks like a disabled plain button, whether it carries disabled itself, is disabled by its <fieldset disabled>, or is a link marked aria-disabled="true". A visible context has at most one .btn-primary; a view that seems to need two has a secondary or destructive action hiding in one of them.

    A toggle button latches. With aria-pressed="true" it stays pressed in until pressed again, and the same attribute tells assistive technology that it is on. A primary button may latch too, such as a flash card's Reveal: it keeps its accent and its text, and loses its lift. Press these three.

    3. Forms

    A field that takes input is sunken. A read-only value is flat, with no field around it, so it never pretends to be editable. A switch is a raised thumb in a sunken track, and when it is on, the track fills with the accent and the thumb sits at the far end, so its position says so as well as its colour. An error leads with its warning glyph.

Related choices, such as radio buttons, sit in a fieldset with a legend, and a file field's button is raised like any other.

    4. Segmented control

    A segmented control offers two to four choices in a sunken trough: a small scale, kg or lbs, Read or Edit. It is a switch with more than two positions, as macOS and iOS draw it: the trough is the track, the chosen choice is the raised thumb, and pressing another position moves the thumb there. Its choices are buttons marked with aria-pressed, or links to views marked with aria-current.

    5. Section tabs

    Section tabs are a notebook, after the widget of the same name in desktop toolkits. The bar is a recessed band. Each tab the reader can go to is a raised tab standing on the band, because it can be pressed. The tab for where the reader is, marked with aria-current, is flat, a little taller, and open at the bottom into the content below, so the page visibly hangs from it. A page inside a section marks that section's tab with aria-current="true", and the section's own page with aria-current="page". The current tab takes --section-current-bg, which a page whose content sits on the page background sets to var(--bg).

    6. Badges and chips

    Three small labels each look like what they are. A badge states an entity's state, done or overdue, and always leads with its glyph as well as its colour. A chip names an attribute the thing carries, such as a tag or a trip, and is a plain neutral label. A filter chip, shown with the master–detail layout below, is a filter in force: it is outlined, and its × is a small raised button that removes it.

    9. Data table

    A data table lists many records, one per row. A column the reader can sort by has a raised header, because pressing it re-sorts, with a glyph showing the column's direction, or two small arrows while it is not the sort. The header is an ordinary link such as ?sort=amount&dir=desc, so sorting needs no script and a sorted list can be shared. Numbers align to the end. A selected row shows a checked box, a tint and an accent edge at its start. When the table is narrow, as on a phone, a table marked .stack shows each row as a small card of labelled values; make this window narrow to see it.

    10. Notices and toasts

    A notice is a message that stays on the page until it is dealt with, and a toast is a passing confirmation that leaves by itself after a few seconds, waiting while the pointer or focus is on it. Both lead with the glyph of their kind and carry a coloured edge, so neither rests on colour alone, and screen readers announce a toast as it appears. An error the reader has to act on is always a notice, because a toast goes away. With pudl-toast.js, a script raises a toast with pudlToast(), and a server can render one into the page after a form redirects.

    11. Tabs within a page

    Tabs within a page switch between panels of one record in place, where section tabs go to other addresses. They look alike, because to the reader both are tabs. With pudl-tabs.js, a tab is chosen by pressing it or with the arrow keys once the tab list has focus, the tab list is a single stop in the Tab order, and the chosen panel's id becomes the address's fragment, so a link can open a particular panel and a reload keeps it. Without the script, every panel shows one after another.

    12. Empty and loading states

    An empty state tells the reader there is nothing here yet and what to do about it. A loading state pairs a spinner with words, in an element with role="status", so it is announced and never rests on the animation alone. The icon buttons on this page, the window buttons and the filter's apply button show a tooltip with their name on hover or keyboard focus, through pudl-tooltip.js.

    13. Pagination

    A long list comes in pages, each an address such as ?page=3, so paging works without script and a page can be shared. The page links are raised; the current page is pressed in, because the reader is already there; and previous and next carry their glyphs and are disabled at either end.

    14. Dialogs

    A dialog is a native <dialog class="dialog"> that the server renders into the page, never the browser's own confirm(). A button opens it with command="show-modal", and the browser keeps focus inside it, closes it on Escape and draws the backdrop, which dims the page gently while the panel's shadow does the lifting. The panel is one step brighter than the page. It offers two actions, the safe one first and the committing one last, and a destructive commit carries its warning glyph. The optional pudl-dialog.js provides the command buttons in browsers that do not have them yet.

    Persistent sidebar handle

    Opt-in layouts keep a raised handle available after collapse and on narrow screens. Desktop dragging resizes the list; narrow gestures request URL navigation from the host. The persistent article reader demonstrates both modes, click/tap resize controls, and Back/Forward navigation. The persistent sidebar guide defines the state and request contract.

    One pane at a time

    When the layout is 640 px wide or less, on a phone or in a narrow window or panel, it shows either the list or one record, never both. Each is its own URL. The server marks the layout with data-md-pane="detail" when the URL names a record, and the record's pane then opens with a back link to the list, which keeps the filters and names the record's row as its fragment so that the list scrolls back to where the reader left it. The list's toolbar and filter chips belong to the list and step aside while a record is showing. The back link returns to the list the record lives in, and is not a breadcrumb trail.     16. Menus

    A menu button opens a panel of choices. The button is raised and carries a caret, so it reads as opening something rather than doing something, and it looks pressed while its panel is open. The panel is lifted like a dialog but has no backdrop, because it is not modal: Escape, a click outside it or a choice closes it. Places in a panel are list rows grouped under section labels, and actions are rows of their own below a rule, each with a glyph. The panel is an HTML popover, so all of that works without script. The optional pudl-menu.js opens the panel against its button, as a full-width sheet on a phone, lets the arrow keys move between rows, and makes a filter at the top of a panel narrow its rows as you type. An open menu is not part of the URL, because it is momentary; everything in it has an address of its own. The Trip and Account buttons in the master–detail toolbar above are menus too.

    A launcher is a menu button at the start of the row that holds a window dock, with a panel that reaches everything a site offers, grouped by category, with a filter at the top. The windows demo below has one, and so does the article reader sample.

    A menu can also be summoned from the keyboard. A panel carrying data-menu-key="/" opens when / is pressed anywhere outside a text field, with focus in its filter, so the reader can type part of a name and press Enter to go there. On this page, / opens the expenses launcher. If nothing matches and the filter sits in a form, Enter submits the form, so a server can take the typed text to a page of its own, which makes the menu a "go to" palette that still ends in an ordinary address. A panel with no button of its own opens near the top of the window, as a palette.

    Application menu bar

    The menu-bar conventions define the site bar and applet bar. Standard site menus appear in the order Site name, Go, Applets, View, Window, Help, with unused menus omitted. Applets is a direct launcher beside Go. Each group begins with an identity menu; working commands have their own menus. The shared site adoption guide applies these rules to Parks Computing and YAVCHN.

    The menu bar at the top of this page is a working example. A bar holds at most two menu groups. The host menu belongs to the application and stays in place. The front menu belongs to the applet or article in front and appears to its right. Each menu is one raised group with a menu glyph at its start. Its titles share that raised surface, and the open title looks pressed. A title opens a panel of commands, which can include links, actions, checked or disabled commands, headings, separators and submenus.

    Try View to change the theme or open the Components submenu. Choose Window, then Open hotel expense to see a front menu appear for the hotel window. Its Receipt title opens the receipt through the same link used inside the window. Bringing another expense forward removes the hotel's menu, while the host menu stays available. Resize the page to see the bar become one menu button when it runs out of room. In that form, choosing a title or submenu replaces the panel's rows and adds a Back row.

    Load pudl-menubar.js after pudl-menu.js, and after pudl-windows.js and pudl-applets.js when those are used. The host supplies a hidden nested list inside nav.menubar[data-menubar]. Each top-level item supplies a title and its commands. Links keep their addresses, and choosing a button command clicks the source button so the application's handler runs. Keep ordinary navigation beside the source list for readers without script; PUDL hides that fallback when it builds the bar.

    <nav class="menubar" data-menubar aria-label="My application">
  <ul data-menubar-source hidden>
    <li>My application
      <ul><li><a href="/">Home</a></li></ul>
    </li>
    <li>Help
      <ul><li><a href="/help">User guide</a></li></ul>
    </li>
  </ul>
  <a class="brand" href="/">My application</a>
  <a href="/help">User guide</a>
</nav>

    An applet supplies its front menu through menus(), returning { titles, into }. Each title has a label and an items list. Commands have a label and run, with optional checked, radio, disabled, danger and shortcut fields, or an items list for a submenu. A string '-' supplies a separator, and { heading } labels a group. PUDL asks for the menu again whenever a panel opens, so its state stays current. An applet that supplies only commands() gets one title containing those commands.

    Host titles declare data-menubar-id independently of their displayed labels. The first title is the site identity. A front menu cannot reuse a reserved site ID or host title. Its into entries add commands only to go, view, and help, below the site commands under a heading naming the applet. Exact host labels remain a compatibility fallback. Empty shared slots appear when populated. A Window title with data-menubar-windows generates standard window management. See the 0.40.0 migration guide for the API and generated identity-menu changes. Command labels must be unique within a panel. PUDL omits clashes and reports them in the console. With a menu bar present, applet commands live there; the window menu retains the window's own controls.

    An article supplies a hidden nav[data-page-menu] containing the same nested lists, with links for its commands. PUDL adds a first title named after the article, with Open as a page, Copy link to this content and, in a window, Close window. Print appears under File. The hotel example uses this form for its Receipt title. A heading link scrolls inside the article's window; a link carrying data-win-open opens its target window.

    Menu bar keyboard controls
    TabEnter the bar at its single tab stop, or leave an open menu.
    Left / RightMove between titles across both menus; inside a panel, open or close a submenu or move to the adjacent title.
    Down / Enter / SpaceOpen the focused title's panel.
    Up / DownMove between commands in a panel.
    LetterMove to the next command beginning with that letter.
    EscapeClose the menu.

    The first title has accesskey="m"; the browser determines its modifier keys. Set data-menubar-key on the bar to change it, or use an empty value to disable it. A command's data-shortcut, or an applet command's shortcut, uses Mod for Ctrl on Windows and Linux or Command on a Mac. This page uses Mod+Shift+L to change the theme. Site-owned shortcuts work anywhere; applet shortcuts, including contributions to the site bar, work only while focus is in their content. Removing or replacing the active source closes its menu. Browser window and tab shortcuts, and the standard select, copy, cut and paste shortcuts, are reserved. See the integration guide for the complete markup and command contract.

    17. Floating windows

    Records can open as windows floating above a list, from the optional pudl-windows.css and pudl-windows.js. Open a few of the expenses below, then drag a window by its title bar, resize it from any edge or corner, drag it against the left, right or top edge to snap it, and double-click its title bar to maximise it. The dock above the list has one tab per open window. Everything you do is written into this page's URL, so reloading puts every window back where it was, and Back undoes the last window you opened.

    The frame around a window is a band of the raised tint between two hairlines, and the whole band is the resize border. The active window's title bar takes the accent. With the title bar focused, the arrow keys move the window, Shift with the arrow keys resizes it, and Enter maximises or restores it. Without script, each link opens the record's own page, and the server renders whichever windows the URL names where the URL puts them.

    A window can have children, for content that belongs to a record, such as a receipt, a source listing or an image. Open the hotel expense and follow its receipt link. The receipt opens maximised above the expense, a row for it appears under the expense in the list, and Escape or the close button puts it away. A child has no tab in the dock, travels with its parent when the parent is minimised or brought forward, and closes when its parent closes. The list also marks the row of the window in front. The article reader sample puts all of this together as a reading site, with the article list in a sidebar and each article opening maximised.

    The sample also shows three things for moving around and for interactive content. A "Next" link at the foot of an article opens the next one in its place, as a link does in a browser tab, and Back returns to the one before. One article holds an applet, a colour mixer, which runs from the same script in the window and in a page of its own, keeping its state in the address only when it owns the page. And scripts can drive the windows through pudlWindows, and hear each window close through the pudl:window-close event, instead of clicking PUDL's buttons.

    A link followed from inside a window opens its window in the same state, so following links never overturns the arrangement: from a floating window, the new one floats a step down and to the right. And the sample's category tabs above the list change only the list. The optional pudl-regions.js swaps the parts of the page a navigation changes, marked with data-region, and leaves the windows as they were, scroll positions and running applets included.

    18. Trees and path bars

    A tree is a hierarchy of places, such as folders, as nested lists of links. Without script it is an indented list; pudl-tree.js makes it one stop in the Tab order, where the arrow keys move, open and close, and typing a name moves to it. Each node with children has a small raised toggle. A path bar says where the reader is inside a hierarchy they are browsing, and only there: a site's sections are its tabs.

    20. Document tabs and code

    Document tabs come and go, one per open file, and look like every other tab. An unsaved document's tab carries a dot, whose word is heard rather than seen, and each tab has a small raised close button; Delete closes the focused tab. The host decides, through pudl:tab-close. A code block is flat, because it is for reading, and an editor's surface is sunken, because it takes input; highlighted code in both takes the theme's --syntax colours. Both show every character as written, with the monospace face's ligatures turned off. A block marked data-code-actions gains a strip naming its language, with raised buttons to copy the code and to download it as a file.

    21. Splitters

    Set --split-target-size: 18px for a wider track that occupies its own space. --split-rule-size controls the visible line. Set data-split-pane="first" or "second" to show one pane while keeping both mounted and preserving the split value; remove the attribute to restore both panes. The host owns the URL state and focus transfer. The responsive workspace guide also covers narrow window policies, compact chrome, menu overflow, and menu-group theme tokens.

    Two panes inside a component, with a handle between them that resizes the first, drawn as the master-detail divider is. Drag it, or focus it and use the arrow keys, Home and End; Enter or a double-click returns the stylesheet's size. The second pair is stacked.

    22. Invariants

    These hold everywhere PUDL is used, and a page that breaks one is not using PUDL as intended.

    • ElevationRaised means the reader can press it, sunken means they can type into it, and flat means it is there to be read.
    • ButtonsEvery button is raised, and a visible context has at most one primary button.
    • ColourColour is never the only signal; every meaningful state carries a glyph, a position or an elevation as well.
    • StateState is marked with the ARIA attribute that states it, aria-current, aria-pressed, aria-checked or aria-selected, so the eye and assistive technology are told the same thing.
    • LinksLinks in text are underlined; the brand wordmark, tabs and list rows are navigation of their own kinds and look like themselves.
    • NumeralsNumerals are tabular wherever numbers are data, and running prose keeps proportional figures.
    • TabsThe tab for where the reader is opens into the content below it, and every other tab is raised.
    • No breadcrumbsEvery full-screen page anchors to a tab somewhere in its hierarchy, marked current. A page that wants to live below the deepest tab strip is either a dialog or a sign that the tabs need another level, not a breadcrumb trail.
    • TopbarA menu-bar topbar follows the light or dark theme, with each menu group slightly raised. Other topbars retain their separate theme colours.
    • DialogsDialogs are native dialog elements rendered by the server, never the browser's own confirm().
    • The URLThe URL holds everything worth sharing, from a record in view to the arrangement of open windows, and the server renders what it names, so a page works without script and a link shows what its sender saw.
    • GlyphsEvery glyph in PUDL's chrome is drawn from the stylesheet's own masks, so it looks the same on every platform and never turns into a colour emoji.
    • TimeTimes are ISO UTC in data and local only on display.
    • RecolourChanging --accent reaches links, primary buttons, focus rings, filter chips, the dots on the dock's tabs and the active window.
