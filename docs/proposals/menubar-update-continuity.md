# Dropdown continuity during background updates

A focus and dropdown defect that blocked work in a host application was found on 1 November 2026. This scoped follow-up targets a patch release after 0.96.1. The Glass and stack typography proposals remain separate.

The work starts with dist/pudl-menubar.js and one focused regression suite, in an isolated worktree on fix/menubar-survives-updates based on main d0a61cb. Unrelated edits in the primary working tree must be preserved.

Command updates should update ribbon controls in place, preserving an open dropdown, its anchor and the focused command when they remain available. A necessary full bar rebuild must restore the focused command by stable identity. If that command is removed or disabled, focus moves to the first enabled row. If the dropdown disappears, focus must return to a surviving appropriate bar control; a detached old dropdown button cannot receive focus. The patch must define and test that fallback against the actual DOM. Command states and labels still update. Escape, outside clicks and action execution retain their normal close behavior.

Focused evidence should use the existing tests/lib.js and tests/run.js harness with isolated output directories, one worker and retained raw/effective exits. Cover redundant command-change events, retitles, changed enabled/checked states, removed commands/dropdowns, keyboard navigation, and ordinary close actions in both menu and ribbon modes. Run readable and minified forms in the applicable engines. Generated minified artifacts, version changes and CHANGELOG are produced at integration, from an immutable implementation commit with its exact paths and evidence.

Each fix gets focused checks, and broad regression runs at batch end. RELEASING.md requires affected tests, light/dark reference review, matching generated files, immutable tag/archive and public download/CDN verification. It does not require a new full serial matrix after each intermediate patch. Independent review must inspect assertions and logs before tagging. The final batch gate will be agreed from the patch scope without repeating unrelated admission work on unchanged skin assets.

## Expanded dropdown contract

The requirement was then broadened to any open dropdown control. A background update must preserve the logical open control, its anchor, focus and ongoing interaction while refreshing labels and enabled/checked state. Replacing a DOM node during a redraw is not genuine owner removal when the same logical control remains. Legitimate Escape, outside-click and activation dismissal keep their existing semantics. Genuine owner removal or unavailability must leave focus on an appropriate surviving control; never restore focus into detached or disabled content. Content removal must retain each component's existing valid empty-state behavior, without leaving an orphaned interactive popup.

The reproduction-driven audit and fixes happen within the same isolated branch. The additional source files in scope are dist/pudl-commands.js, dist/pudl-menu.js, dist/pudl-combo.js, dist/pudl-listbox.js and dist/pudl-windows.js, alongside the menu bar, and focused component tests and fixtures may be added as needed. This proposal holds the contract, and the audit and implementation decisions are recorded in docs/proposals/menubar-update-continuity-handoff.md.

Audit command-driven toolbar menus, command choice menus, combo boxes, listboxes, window status popovers, taskbar stack lists and context menus. For each, record the actual background-update path, a reproduction or evidence that it already preserves state, and any affected shared helper. Preserve stable item identity and component-specific interaction such as combo input text/caret/composition, list selection and popup scroll position. Do not steal focus when the reader has moved it elsewhere. Refresh stale command state even while a menu remains open, and execute current command semantics on activation.

Use scoped commits for each demonstrated defect. Do not apply blanket close suppression or a global reopen workaround. Focused tests should prove background-update continuity and normal dismissal, plus item/owner removal and disable fallbacks. Cross-component regression runs once at the batch end. The menu bar fix alone cannot establish coverage for the other controls.

## First patch review

The first candidate is source/test commit 50db4f40af2ad0ecc7bcc4d526537c2ec98562a6 with separate generated commit c2b42a8987c2c8f21c9aa9c248e20c96f82a1e4b. Its author's focused readable/minified cross-engine checks pass, and an unfixed control fails ten checks. These results await independent review.

Initial source review finds a contract gap. The ribbon still replaces its toolbar, calls showPopover on a new panel, and restores focus after a toggle event. That establishes eventual reopening, but does not yet establish uninterrupted open state or interaction through an update. The state capture also does not retain popup scroll position. The new tests settle after updates and use short lists, so they cannot detect either a transient close/focus loss or scroll reset. Before acceptance, preserve the live logical popup and anchor through redundant/state-only updates, or demonstrate equivalent uninterrupted behavior for necessary structural replacement. Add long scrolled-menu and update-during-interaction evidence, including state immediately across updates and dismissal/focus events. Existing pass results remain valid for their narrower final-state checks.

Independent source review of 50db4f4 requires revision (tests/output/menubar-continuity-50db4f4-independent-source-review.md). Narrow/collapsed in-place submenu paths must survive updates. Disabled dropdown owners must not be reopened or retain actionable children; runtime checks must use the actual command availability, with matching button state. The shared menu observer's scroll reset on child replacement must be addressed by the continuity design.

The selected fallback remains the first enabled row in the surviving current menu, as specified above. Nearest-row fallback is not selected. If that submenu is unavailable, use its enabled parent row in the surviving parent menu, otherwise the first enabled row there, then an appropriate enabled surviving bar control. Tests must assert this deterministic order and cover identity-preserving rename/reorder, owner disable, narrow submenu paths, scroll retention and update/dismissal/focus races. This clarifies the existing proposal and supersedes the first patch's nearest-row behavior.
