## Expanded dropdown contract

Paul broadened the requirement to any open dropdown control, relayed in messages 2976 and 2978. A background update must preserve the logical open control, its anchor, focus and ongoing interaction while refreshing labels and enabled/checked state. Replacing a DOM node during a redraw is not genuine owner removal when the same logical control remains. Legitimate Escape, outside-click and activation dismissal keep their existing semantics. Genuine owner removal or unavailability must leave focus on an appropriate surviving control; never restore focus into detached or disabled content. Content removal must retain each component's existing valid empty-state behavior, without leaving an orphaned interactive popup.

Front End owns the reproduction-driven audit and fixes within the same isolated branch. Additional owned source files are dist/pudl-commands.js, dist/pudl-menu.js, dist/pudl-combo.js, dist/pudl-listbox.js and dist/pudl-windows.js, alongside the menu bar. Front End may add focused component tests and fixtures as needed. No other known active writer owns these modules. Any further module requires an explicit ownership notice before editing. The lead maintains this primary proposal; Front End records its audit and implementation decisions in the branch handoff.

Audit command-driven toolbar menus, command choice menus, combo boxes, listboxes, window status popovers, taskbar stack lists and context menus. For each, record the actual background-update path, a reproduction or evidence that it already preserves state, and any affected shared helper. Preserve stable item identity and component-specific interaction such as combo input text/caret/composition, list selection and popup scroll position. Do not steal focus when the reader has moved it elsewhere. Refresh stale command state even while a menu remains open, and execute current command semantics on activation.

Use scoped commits for each demonstrated defect. Do not apply blanket close suppression or a global reopen workaround. Focused tests should prove background-update continuity and normal dismissal, plus item/owner removal and disable fallbacks. Cross-component regression runs once at the batch end. The menu bar fix alone cannot establish coverage for the other controls. Final publication and generated artifacts remain the lead's responsibility.

## First patch review

Front End supplied source/test commit 50db4f40af2ad0ecc7bcc4d526537c2ec98562a6 and separate generated commit c2b42a8987c2c8f21c9aa9c248e20c96f82a1e4b. Initial lead source review finds a contract gap. The ribbon still replaces its toolbar, calls showPopover on a new panel, and restores focus after a toggle event. That establishes eventual reopening, but does not yet establish uninterrupted open state or interaction through an update. The state capture also does not retain popup scroll position. The new tests settle after updates and use short lists, so they cannot detect either a transient close/focus loss or scroll reset. Before acceptance, preserve the live logical popup and anchor through redundant/state-only updates, or demonstrate equivalent uninterrupted behavior for necessary structural replacement. Add long scrolled-menu and update-during-interaction evidence, including state immediately across updates and dismissal/focus events. Existing pass results remain valid for their narrower final-state checks.

Independent source review of 50db4f4 requires revision (message 2986; tests/output/menubar-continuity-50db4f4-independent-source-review.md). Narrow/collapsed in-place submenu paths must survive updates. Disabled dropdown owners must not be reopened or retain actionable children; runtime checks must use the actual command availability, with matching button state. The shared menu observer's scroll reset on child replacement must be addressed by the continuity design.

The selected fallback remains the first enabled row in the surviving current menu, as specified above. Nearest-row fallback is not selected. If that submenu is unavailable, use its enabled parent row in the surviving parent menu, otherwise the first enabled row there, then an appropriate enabled surviving bar control. Tests must assert this deterministic order and cover identity-preserving rename/reorder, owner disable, narrow submenu paths, scroll retention and update/dismissal/focus races. This clarifies the existing proposal and supersedes the first patch's nearest-row behavior.
