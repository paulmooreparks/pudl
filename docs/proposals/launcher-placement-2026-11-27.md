# Launcher placement correction

Cold reproductions on live main 8e25327b were saved before product edits under tests/output/launcher-placement-20261127/original. Exact source hashes are in source-before.json; the test, fixture, failed receipts, frame geometry, screenshots and cold-context WebM recordings are retained. The wide ribbon panel covers its generated opener. The short desktop panel changes visible geometry across frames. Both prevent the second ordinary pointer click from closing it. Original cases do not pre-open or prime the panel.

The original visible getter returns the retained product tab when it has layout boxes. The host's explicit anchor callback therefore anchors above the generated ribbon row. The corrected getter preserves no-argument identity and resolves a live generated launcher opener only for visible lookup, with live fallback controls and no stale cache.

The original launcher place() measures popup height before changing --launcher-top, while CSS max-height depends on that variable. The short case repeatedly shrinks/repositions through observer frames. The correction computes the anchor, available side and explicit border-box width/height/constraints before opening. Native beforetoggle prepares the same geometry synchronously. It measures no display-none popover and uses no elapsed-time reveal assumption. Height shrinks below the whole opener instead of clamping upward over it. Explicit anchors and above/taskbar placement retain precedence, and requested desktop size remains separate from temporary viewport constraints.

No pudl.css change is proposed at this boundary. The controller can set its own inline popup size constraints and clear them when entering a pane; destroy restores the original style. HTML popover processing documents beforetoggle before showing (https://html.spec.whatwg.org/multipage/popover.html#show-popover). CSS border-box sizing makes configured width/height include the border box (https://www.w3.org/TR/css-sizing-3/#box-sizing). Geometry measurements are of visible anchors; popup dimensions are explicitly configured, not inferred from hidden layout (https://drafts.csswg.org/cssom-view/#dom-element-getboundingclientrect).

The additional original menu cases in candidate-1 show cold native title activation before later toggle placement, including a first sampled rectangle at (0,0). This must not be attributed to a proven synchronous present() path. Both the controller-open path and native beforetoggle now prepare the same explicit geometry before show; later toggle and observer calls reuse that calculation. The candidate fixture corrects inherited corrupted Updates and close-glyph text with HTML entities; the corrupted original fixture remains retained.

The effective desired height includes the existing 260px minimum before automatic side choice and final positioning. The requested dimensions remain separate from viewport limits.
