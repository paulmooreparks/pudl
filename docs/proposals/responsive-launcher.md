# Responsive launcher presentation

The approved responsive policy uses one compact breakpoint, 650 CSS pixels by default. Hosts can set `compactAt` to another nonnegative width or false to retain desktop-only presentation. A host taskbar gets a leading launcher control automatically when the configured invoker is elsewhere. An existing taskbar invoker is reused. The taskbar control is mandatory in compact mode; on desktop it is hidden when a directly available site-title launcher exists, unless `taskbarAlways` is true. Hosts retain responsibility for supplying a taskbar and a connected workspace layout.

In compact mode, the existing catalog fills the workspace rectangle between the host header and taskbar. It uses a manual popover so unrelated clicks do not dismiss it. It has no floating frame or resize affordance, and its Pin control is hidden. Closing and destination activation return to content. Accepted taskbar window and stack selections also dismiss the compact catalog; modified native link activation leaves it intact. The desktop presentation preference is retained separately from compact visibility and restored on widening. A responsive transition never changes that preference or overwrites requested popup and pane dimensions with viewport-constrained geometry. Browse/search focus continues to follow actual invocation intent.

The Size button remains enabled. Floating presentation offers width and height. A pinned side pane offers width only; a stacked layout offers height only. Compact presentation hides numeric fields, explains automatic sizing and offers Reset saved desktop size. A reset restores popup defaults from `defaultSize`, and pane defaults from `defaultPaneSize` or the layout stylesheet. Saved popup `size` and optional `paneSize` remain separate inputs. `pudlLauncher.resetSize(root)` and `data-launcher-reset` use the same implementation.

Optional `compactVisible` restores compact visibility independently on initialization. State adds `compact`, `visible`, `paneAxis` and `paneSize`. During compact presentation, `presentation` remains the saved desktop preference. Hosts must persist the preference and requested dimensions, rather than infer them from the compact DOM or effective bounds. Explicit API presentation and pin changes can update the saved preference; opening, closing and selecting items in compact mode only change current visibility.

## Outside-focus Escape correction

Real-host beta testing retained a two-Escape sequence in which Windows closed but the catalog remained open after focus returned outside it. The compact catalog is a manual popover, so native auto-popover dismissal does not close it. The Start key handler also applies only within the catalog. The launcher now handles a remaining unhandled Escape at document level, after menu handlers, provided there is no other open popover or modal dialog. It restores opener focus without changing the desktop preference. The new regression reproduced the failure in all three engines before correction and checks nested dismissal priority, outside focus, handled events and desktop isolation. Browser-error gates remain enabled.

The outside-focus Escape regression passed 3 readable runs and the affected minified matrix passed 21 runs across Chromium, Firefox and WebKit. The earlier readable matrix retained 20 passes and a desktop fixture failure caused by asserting before the responsive resize transition completed. That fixture now awaits desktop state before checking desktop Escape isolation. The original two-Escape defect failed in all three engines before the source correction. Evidence is retained under `tests/output/launcher-escape-*`. Syntax, minifier freshness and whitespace checks pass. The replacement requires fresh beta verification.
