# Independent taskbar height review

The required normal rendered height is 30px for every taskbar button, including individual actions inside the tray. The tray's outer box must also remain 30px. The earlier proposal for 26px tray actions and a separate 40px coarse-pointer height does not satisfy Paul's all-buttons instruction. This document records Verification's policy and coverage disposition for assignments 11079 and 11083; implementation and rendered outcome acceptance remain pending.

Paul's exact wording, relayed by the lead in 11083, is: "I want a 30px height to match the bordered tray height. This should apply to all buttons on the taskbar so that they are a consistent height." The earlier request also asks for a visible stacking indicator at that height. This chat cannot read the Team Leads group directly; the lead supplied the literal request after the bus denied access. The revised implementation proposal in 11084 and charter clarification in 11085 follow that wording.

## Policy disposition

| Question | Required behavior and reason |
| --- | --- |
| Which rectangles must equal 30px? | Ordinary window entries, stack buttons, authored actions, icon buttons and each actionable tray item must individually equal 30px at the normal root text size. Measuring only the outer tray cannot establish this. |
| May the tray become 34px around 30px actions? | It must remain 30px. Remove taskbar-scoped layout overhead and paint its boundary inward. Retain the visible bordered-tray appearance and applicable customization variables. The base status-area styling outside taskbars must remain unchanged. |
| Does the old coarse-pointer height win? | It does not. Remove the taskbar's conflicting 40px block-size override. Its existing 40px minimum width can remain because the request concerns equal heights. Assert the actual pointer media state and resulting action heights; do not infer touch coverage from viewport width. |
| May enlarged text grow the row? | Shared growth is required to keep content usable. Every peer, tray and inner action must consume the same resolved length. Untyped custom-property values containing em units can resolve at different consumer font sizes, so merely defining such a value on the bar does not prove equal lengths. |
| Do stack faces count as taller buttons? | The foreground button remains 30px. Rear faces retain their 2px and 4px offsets within the dock's reserved paint space. They must remain distinguishable, contained and associated with the same chooser button. |

The baseline at merged speed commit 8d580821abfc897e6ddb04cfab0f4d5ad7e266d6 has the accepted speed tree and no taskbar-height repair. In dist/pudl-windows.css, the peer rule uses a font-relative fallback while the coarse-pointer rule overrides it to at least 40px. In dist/pudl.css, status-item has a fixed 26px height and status-area adds its border/padding. The repair therefore needs both the shared sizing and a taskbar-scoped tray treatment; changing only peer height leaves the explicit inner-action requirement unmet.

An inset outline is a candidate paint mechanism rather than an accepted rendered result. The [CSS UI outline specification](https://www.w3.org/TR/css-ui-3/#outline-offset) documents non-layout outline painting and offsets. Source review must check that inner hover/active backgrounds do not cover the tray boundary, that keyboard focus remains visible, and that forced colors retain an actual boundary rather than relying solely on a shadow. Browser measurements and visible boundary evidence still need to confirm the implementation.
